# Visible object shapes applied to the frame 0 reference

Each case folder contains:

- `frame0_reference.png` in cases with a usable frame 0: the RGB pixels of the frame 0 SAM3 object, with a transparent background. It is absent when frame 0 fails the link7 guard or is already substantially overlapped by link7.
- `masks.npz`: `available_pure_object[T,H,W]` (object SAM3 minus link7 SAM3), `mapped_to_frame0[T,h0,w0]`, `mapping_valid[T]`, `mask_valid[T]`, the cropped frame 0 object mask, and its full-frame bounding box.
- `manifest.json`: frame-by-frame area, expected-silhouette coverage, detector reference frame, and mapping status.
- `examples/frame_XXXXX/`: the chosen frame's visible RGB pixels, the corresponding RGB pixels from frame 0 under the mapped shape, and a three-panel `preview.png`.

The current-frame visible mask is exact at the SAM3 pixel grid. Mapping to frame 0 uses the existing occlusion detector's full-object silhouette, scales its bounding box to the frame 0 object bounding box with nearest-neighbor sampling, and clips to the frame 0 SAM3 mask. This preserves the visible region's binary shape at the reference crop resolution. It does not establish exact material-point correspondence under rotation or deformation.

The export covers 45 cases and 4,965 frames; 4,518 pass the mapping rule. The area guard rejects 98 frames in LVP010 and LVP015. Failed frames have no available pixels or mapped crop, and `mask_valid` is false. Their old example crops are removed when the case is re-exported. Other mapping failures retain their recorded reasons in each manifest.

```sh
PYTHONPATH=PDI-Bench-edited/src /opt/homebrew/bin/python3 -m pdi_eval.object_deformation_wrapper.reference_visible_pixels \
  --object-root results/object-deformation-selected45-20260929 \

  --render-only --cases COSMOS3_0056 --frame 115
```

Replace the case and frame number as needed. `mapping_valid` is false where frame 0 is already contaminated by link7, the detector has no full-object estimate, the object has no visible pixels, or less than 80% of its visible pixels lie inside the estimate's bounding box. Always check that flag before using a mapped crop. The per-frame available mask is empty when `mask_valid` is false; skip those frames entirely.

## Ten-frame selection and anomaly scores

**[Open the crop gallery](selection_gallery.html)** — anomaly scores for each selected crop pair and a summed score for each scored video.

Each video uses quotas **0/2/2/2/4** across 0–20%, 20–40%, 40–60%, 60–80%, and 80–100%. Usable immediate post-occlusion successors are mandatory and consume their interval slots. Other frames rank by visible object area within each interval; earlier frames break ties. Missing interval slots fill from the latest available allowed interval first. The first 20% is excluded except for mandatory recovery frames. There is no additional temporal-spacing constraint.

The updated export has **410 pairs across 41 usable videos**, including 15 mandatory recovery frames and 12 interval replacements. Two immediate successors remain unusable and are explicitly reported in selection notes. Four videos cannot supply reference crops: COSMOS2.5_0021, LVP_ROBOWM_0010, LVP_ROBOWM_0015, and LVP_ROBOWM_0060.

AnomalyDINO scores **350 pairs from 35 videos**, with the same six exclusions: COSMOS2.5_0001, COSMOS3_0001, LVP_ROBOWM_0001, COSMOS2.5_0005, COSMOS2.5_0010, and COSMOS2.5_0065. Higher scores mean more anomalous. Video totals sum ten original unrounded pair scores; excluded or unavailable videos have no numeric total. These new totals aggregate twice as many pairs as the previous five-frame run.

The existing saved masks, silhouette mapping, and official per-pair AnomalyDINO calculation are reused. [Completed ten-frame experiment](../anomalydino-object-crops-10frames-20261002/README.md).
