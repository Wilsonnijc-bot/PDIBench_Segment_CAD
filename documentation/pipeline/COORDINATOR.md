# Resumable robot/object coordinator

`python -m deformation_detect coordinate` replaces the validation-only `masking_driver.py`, `downstream_driver.py`, and `case_tasks.py`. The coordinator runs the existing numerical implementations in their own environments, with explicit inputs and immutable stage attempts. It does not publish the results website or run object geometry/rigidity.

Copy [coordinator.example.json](coordinator.example.json) and fill in the installed environment, model, reference, video and output paths. Paths are relative to the manifest file unless absolute. Credentials belong in environment variables or the external `secrets_file`, never in this manifest. Environment variable names may be configured in public VLM role settings; their values are not serialized.

```bash
python -m deformation_detect coordinate --manifest run.json --plan
python -m deformation_detect coordinate --manifest run.json --preflight-only
python -m deformation_detect coordinate --manifest run.json
python -m deformation_detect run-status --output /path/to/runs/link7-object-run
```

Run the same command again to resume. A disabled case remains disabled with unchanged inputs; `--retry-disabled` explicitly grants it a new attempt budget. Changed inputs automatically invalidate the affected stage and its dependents. A run exits 0 when every case completes, 2 when some cases are disabled. A preflight/configuration failure stops the run before inference.

For concurrent videos in one GPU allocation, set `"execution": {"workers": 10, "gpu_slots": 2}` in the manifest, or pass `--workers 10 --gpu-slots 2`. Each video runs the same coordinator in a separate process under `cases/<video>/`, with its own state, lock and immutable attempts. The parent retains one `run.json` and review index, plus per-video coordinator logs and independent exit files under `coordination/`. Shared preflight and resource identities are computed once per launch. GPU admission uses OS file locks around each stage; waiting for the first admission does not consume that stage's VLM retry time budget. Crashes release admission locks automatically. SIGTERM cleans active per-video coordinators and their model-worker process groups.

`workers` controls active video coordinators; `gpu_slots` controls concurrent model stages. Ten coordinators can be active while two stages occupy one H200. Increase GPU slots only after measuring memory and throughput under the deployed models. Resume accepts different worker/slot counts without invalidating scientific outputs. A serial output and a parallel output have distinct layouts; start a fresh output to switch layouts. Existing manifests retain serial behavior by default.

For multiple allocated GPUs, set `"gpu_assignment": "per_video"` inside `execution` (or pass `--gpu-assignment per_video`). The parent pins each active video coordinator to one entry from the scheduler's `CUDA_VISIBLE_DEVICES`; nested model interpreters inherit that single GPU. It requires at least as many allocated GPUs as active video workers and fails before launching cases if the allocation is insufficient. This supports, for example, two scheduler jobs with five GPUs, five workers and five stage slots each. Resource requests and scheduler quotas still determine how many groups can run at once. Per-video coordinator execution receipts record the actual GPU assignment.

Every pipeline Python subprocess receives a fresh workspace search path and an import guard. Archived infrastructure and foreign copies of maintained namespaces are rejected before import execution. Actual origins are recorded under each attempt's `import-origins/`, including nested interpreters, for production acceptance review.

Use the existing job supervisor or a unique tmux session for a remote GPU run. The coordinator itself writes durable `run.json`, per-attempt logs, and `index.html`. It needs no per-video shell script. It is a foreground process: stopping the terminal without a supervisor can interrupt it. Keyboard interruption or SIGTERM terminates the active worker process group and records the interrupted stage. If the coordinator is killed without cleanup, resume refuses to start while the recorded worker is still alive. An unfinished worker on another host requires resolving its ownership first. Never run two coordinators against the same output; a filesystem lock enforces this.

## Stage boundaries

For a gripper/object masking replay without downstream measurement, set `"mode": "masking"` in the manifest. The coordinator completes stages 1–5 through `mask_join`, including persistent validation and any required VLM3 repair. Export the selected Link7 archive together with the object archive. Omitted `mode` keeps the full pipeline; switching a completed masking run to `"mode": "full"` reuses verified masks and continues downstream.


1. Robot initial DINO/SAM3 masks.
2. VLM1 frame diagnoses, followed by VLM2 point selection.
3. Persistent SAM propagation and native validation.
4. Object grounding and SAM masks.
5. Joint mask selection: either object overlap >95% or link7/image area ≥25% triggers VLM3. One committed selected mask feeds both downstream branches.
6. Object CoTracker, existing occlusion detector, available-pixel crop mapping and ten-pair selection.
7. Optional Link2 DINOv2-guided SAM3 masking and Link5 VLM-guarded SAM3 masking, then shared native MegaSAM + V1/CoTracker rigidity and interactive replay for the requested robot links.
8. Object AnomalyDINO and scored crop gallery.

Each video has its own coordinator and executes its full DAG end to end; multiple video coordinators share one H200. Object CoTracker has no dependency on link7 masks. Occlusion/crops require the selected link7 mask. Numerical occlusion, tracking, crop selection, anomaly and rigidity functions remain shared with the existing interfaces.

The owner adapters are [robot/workflows/coordination.py](../../robot/workflows/coordination.py) and [object/workflows/coordination.py](../../object/workflows/coordination.py); execution/state lives under [infrastructure/deformation_detect/](../../infrastructure/deformation_detect/coordinator.py). Legacy experiment entry points remain available.

## Inputs and portability

Case IDs are arbitrary safe names. No historical dataset directory aliases or previous score/occlusion artifacts are required. Supply the original generation prompt for object grounding. An optional `vlm1_reference` supplies the nondeformed reference; without it, the existing pipeline uses the initial mask's frame-zero crop.

Set `"robot_links": ["link2", "link7"]` to include link2 (enabled in the example manifest). Existing manifests that omit this field retain link7-only behavior. Link2 uses the maintained DINOv2-guided SAM3 single-target segmenter with reference spatial priors, 0.10 box padding and the native 0.80 tracked-frame threshold. Supply `resources.robot_references` as the existing reference root containing `by_link/link2` through `by_link/link7`, or the `by_link` directory itself. Preflight validates those groups; SAM propagation targets only link2. No persistent masking or VLM1/VLM2/VLM3 calls are added for link2.

`link2_masks` owns its mask, native diagnostics and provenance. Only `robot_score` depends on it: that adapter combines the fresh link2 mask with the selected link7 archive in its own attempt directory, reuses one native MegaSAM reconstruction, and requests both named rigidity scores/replays. Object occlusion/cropping continues to consume the original joint link7/object handoff. Changing link2 references or corrupting its output invalidates link2 masking and robot scoring, not the object branch or persistent link7 masking. Link2 receives the normal non-VLM failure policy (one attempt, then case disabled until an explicit retry). Each video retains ordered stage execution inside its coordinator; other video coordinators run independently on the shared H200.

To include Link5, set `"robot_links": ["link2", "link5", "link7"]` (or `["link5", "link7"]`) and provide `resources.link5_guard_reference`, the full-frame LVP040 reference image used by the maintained Link5 guard (`documentation/data/references/link5_guard/lvp040_reference_frame.png`). The coordinator runs the same DINOv2 localization and SAM3 segmenter as Link2, with the native Link5 text prompt and extended box. Two independent VLM reviews retain/correct the wrist negative points N1/N2 and forearm positive points P2/P3; P1 remains the localized seed. **The coordinator sends exactly three positive and two negative points to SAM3.** The standalone workflow retains its existing additional joint negative.

`link5_masks` owns the two reviews, input annotations, selected points, SAM propagation diagnostics and mask provenance. Both reviews must be usable; null/malformed/rejected responses cannot silently become an unreviewed mask. It inherits the configured VLM2 endpoint/model, uses the coordinator's deferred timeout queue, and switches to the Luna alternate (at least 600 seconds per request) after a semantic response failure. Four logical attempts and the existing active stage budget bound the work. A valid `REJECT` response containing replacement points is a successful correction. Native SAM point-membership and shaft-retention diagnostics remain informational; no new mask acceptance gate is introduced.

Only `robot_score` joins the fresh Link5 mask with the other requested robot links. It uses the same native MegaSAM reconstruction, exact-group CoTracker/V1 scoring and named Link5 interactive replay as Link2. The selected Link7/object archive is immutable and remains the object branch's input. Link5-only resource changes or corrupted Link5 outputs invalidate Link5 masking and robot scoring without recomputing the object branch. Existing Link2/Link7 manifests remain valid without a Link5 guard reference. The review index includes Link5's replay when produced.

The combined robot mask changes background exclusion and geometry context compared with a link7-only archive. Numerical equivalence to a link7-only run is therefore not implied. The native algorithms are unchanged.

An optional case `base_segmentation` preserves the other robot channels and replaces only the named `link7` mask. Supply it to reproduce the six-link benchmark context. Without it, the joint handoff contains a real single-link archive; when enabled, fresh Link2 and Link5 masks are added or replace their named channels only in the robot scoring input. No dummy channels are introduced. Background tracking/geometry context can consequently differ from a six-link run. Cropping and replay resolve link7 by name.

Preflight checks input readability, all required resource paths, reference images, replay assets, credentials, actual module imports, CUDA operations and key MegaSAM checkpoints. Install/pin the existing third-party forks and model environments first using the [GPU requirements](../gpu/DEPENDENCIES.md). Deployment installation is deliberately separate from case execution. Model/resource contents and environment versions are included in resume identity. MegaSAM writable scratch is isolated per scoring attempt and removed after successful scoring; required geometry and replay artifacts are retained.

## Bounded VLM attempts and failure handling

The default is one initial attempt plus three further attempts per VLM stage. This is a stage-level budget, not three retries multiplied by hidden HTTP retries: the coordinator sets native cloud transport attempts to one. The default active whole-VLM-stage time budget is 3600 seconds across its attempts (time spent in the deferred queue is excluded); other stages have a 14400-second execution timeout. Both are configurable. Interrupted VLM attempts consume the recorded budget; explicit `--retry-disabled` is required to reopen an exhausted budget.

- **VLM1:** retry failed/unparseable frame responses, retaining successful diagnoses. Valid no-deformation results proceed with the initial mask. An invalid response or a sequence with no assessable frames cannot masquerade as no deformation. An optional `vlm1_fallback` public role configuration switches subsequent attempts; otherwise the same configured role is retried.
- **Link5 guard:** P1/P2/P3 are all placed by the VLM using the fixed initial reference. Negative parsing failures and failed N1 box checks retry the same inputs at most three times. Exhaustion disables the case without restarting Link5 masking. N2 need not be in the box. The negative-only review helper preserves cached positives.
- **VLM2:** an initial logical attempt comprises positive and negative point requests. Null/malformed responses and rejected points use the Luna alternate on the next logical attempt. A no-response timeout instead yields the video and retains its current model for the later retry. Luna requests have a minimum 600-second timeout. The old nested one-call alternate is disabled for coordinator execution. Thus four logical attempts can make at most eight point requests, not four requests total. Each attempt retains exact input images, responses and its failure evidence.
- **Object grounding/SAM:** retain the existing configured model sequence and native error handling. The robot-side typed timeout/Luna fallback edits do not change object grounding.
- **VLM3:** one repair candidate per attempt, switching to Luna after a rejected response/candidate; a timeout yields and retains the current route. Preserve the same gate frame, prompts, membership checks and crop-exclusion policy. Validation feedback is carried to the next attempt.

A required VLM3 repair that exhausts its budget disables the case; it never silently falls back to the suspect core mask. Accepted repairs with allowed frame exclusions remain usable. Unexpected mask/scoring/crop failures disable the case rather than fabricating results or aborting unrelated cases. **Insufficient CoTracker tracks on Link2, Link5 or Link7 is an expected completed measurement outcome:** keep its native tracking evidence, record `rigidity: null` and `outcome: insufficient_cotracker_tracks`, and continue object anomaly scoring. Other scoring errors retain the existing failure policy. The review index labels unavailable scores explicitly. Non-VLM stages are not automatically repeated four times. Completed numerical results can still contain quality flags such as a failed native scale-jump audit; those remain visible in metrics and are not rewritten into passes.

No-response timeouts carry typed `vlm_timeout` evidence from the request client through native provenance to the worker/coordinator. The coordinator commits `deferred` state, saves the failed attempt, releases admission/worker ownership, and resumes that video after other cases. Serial execution uses a FIFO tail queue. Parallel execution finishes all original cases in that **allocation/batch** before launching the deferred wave; each child uses exit3 to signal a durable deferral. There are still at most four logical attempts per stage across all waves, not four new attempts every time a video is requeued. A timeout on the last attempt disables the case. Resuming a deferred run keeps its consumed attempt budget, current model, successful predecessor hashes and semantic feedback. VLM1 retains successful frame diagnoses. HTTP errors/other transport failures retain existing handling; they are not guessed to be no-response timeouts.

Separate Slurm groups have separate queues: group A can enter recovery while group B is still running. A global barrier after both groups requires the outer scheduler controller described in [EXPERIMENT_RUNNER.md](EXPERIMENT_RUNNER.md); it is not implemented by this per-allocation queue.

## Resume and output contract

The output contains a single review index, run state, sanitized manifest, environment preflight record, and `robot/<case>/<stage>/attempt-NNNN` and `object/<case>/<stage>/attempt-NNNN` trees. Stages record content hashes of outputs, inputs, dependencies, model resources and implementation sources. Corrupt or missing artifacts are recomputed; changed object prompts do not rerun initial link7 masking. Implementation changes conservatively invalidate all stages. Completed predecessor artifacts are immutable: native persistent work and annotated crop selections are copied into the next stage's owned attempt before modification.

Failures and superseded attempts stay available for diagnosis. This initial implementation favors traceability over storage deduplication; persistent stage snapshots duplicate some masks/images. It does not automatically delete old attempts. Output directories must be new/empty or belong to the same run ID. Deployment/model errors fail preflight rather than spending every video's retry budget.

The earlier saved-artifact checks (214 tests and19 subtests;40 crop PNGs and detector rows identical) remain historical adapter-parity evidence. They are separate from fresh inference acceptance.
